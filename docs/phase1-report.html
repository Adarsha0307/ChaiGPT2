PS-02 Privacy Gateway

A gateway that sits between a company's documents and a cloud AI model. It finds Indian personal data such as names, Aadhaar and PAN, swaps each one for a placeholder before anything leaves the laptop, and puts the real values back into the AI's answer.

Highlighted text is real personal data. Green chips are placeholders. The table that links each placeholder to its real value stays in memory for one request only. It is never sent, logged or saved.

Workflow

One request, six steps

Every caller uses the same function, process(): the Streamlit UI, the FastAPI endpoint and the evaluation script. Phase 1 built this whole pipeline end to end. Three privacy steps are placeholders that pass text through unchanged, so the UI can be built now while Phases 2 and 3 fill them in.

Privacy by design

Safeguards already in place

The AI only sees placeholders

The Gemini code path only ever receives the finished prompt, which is built from masked text.

Proof of what left

Every response records the exact outgoing text, so the leak guard and the audit log check what really went out.

Blocked, not forwarded

If the leak guard fails, process() stops and sends nothing. This rule is already in the pipeline.

The value table is short-lived

The placeholder-to-value table is never logged, saved or sent, and it is thrown away after each request.

Detection runs locally

Presidio, spaCy and GLiNER all run on the laptop. No personal data goes to a detection service.

Secrets stay out of Git

The API key lives in a .env file that Git ignores. A retry resends the same masked prompt, so nothing new goes out.

Engineering log

Problems found and fixed during Phase 1

Problem

The GLiNER model would not load. Its tokenizer failed with a confusing tiktoken error.

Fix

Found the real cause: a missing protobuf package. Installed it, added it to requirements.txt, and added a setup check for it.

Problem

Gemini returned 404. The planned model, gemini-2.5-flash, is retired for new API keys.

Fix

Listed the models the key can use and moved to a current one. The model can now be set in .env without a code change.

Problem

The newest Gemini models sometimes returned 503 errors when Google's servers were overloaded.

Fix

Automatic retry with growing waits of 2 s, 4 s and 8 s, for overload and rate-limit errors only. Bad keys and bad requests still fail right away. 4 tests cover this.

Finding

The plan assumed GSTIN needed a hand-written regex.

Result

Presidio's docs show a built-in GSTIN recognizer that validates the format, so Phase 2 has less to write and is more accurate.
