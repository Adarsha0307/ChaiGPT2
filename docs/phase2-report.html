Workflow

How detection works

Two detectors run on the same text, each doing what it is best at. Their findings meet at the merge step, which decides the final list.

INPUT

Document text

Loan form, KYC record, support ticket, insurance claim. English or Hinglish.

→
LANE A · RULES

Presidio

Patterns, checksums and nearby keywords find Aadhaar, PAN, GSTIN, Voter ID, Passport, phone and email.

LANE B · AI MODEL

GLiNER

Reads the meaning of the text to find names and addresses. Long documents are read in overlapping 200-word chunks.

→
MERGE

Combine the findings

Removes duplicates and settles overlaps. ID numbers win over names and addresses. Nothing flagged gets dropped.

→
OUTPUT

Entity list

Each item has its type, exact position, text, confidence and detector, ready for the Phase 3 masker. Repeats of a value are marked too.

Lane A · Rules

How each ID is recognized

Presidio checks each candidate in up to three ways: does it have the right shape, does its built-in check digit add up, and is a telling word nearby such as "PAN" or "Aadhaar". We load only these 7 recognizers. Presidio's others, like credit cards, IP addresses and dates, are switched off so they can't raise false alarms.

Confidence scores

How a keyword turns a weak match into a find

Every candidate gets a score from 0 to 1, and only scores of 0.40 or higher count. A keyword nearby adds +0.35. Strong evidence passes on its own. Weak evidence needs a keyword.

Lane B · AI model

Names and addresses

Names and addresses have no fixed format, so rules can't find them. We use GLiNER, a small AI model built to find personal data. It runs on the laptop's CPU with no internet connection.

Main path: GLiNER

Model urchade/gliner_multi_pii-v1, trained on many languages, so it copes with Hinglish. We ask it for two labels, person and address, and keep answers it is at least 50% sure of. Long texts are split into 200-word windows that overlap by 30 words, so a name at the edge of one window is still read whole in the next.

Priya Nair · Flat 4B, Shanti Apartments, MG Road, Bengaluru 560001

Backup path: spaCy + address rules

If GLiNER ever fails to load, detection switches automatically to spaCy's name finder plus an Indian address pattern: house or flat number, locality words like Nagar, Road, Sector, Colony or Vihar, and a 6-digit PIN code. This was the plan's fallback for the 6:50 checkpoint. It wasn't needed, but it is built and tested.

The merge step

Four rules that put privacy first

When two detectors find overlapping text, the gateway has to decide what to keep. Each rule is designed so that nothing found is ever left visible.

1 · The longer match wins

A GSTIN contains a PAN inside it. The full GSTIN is kept, so the PAN isn't masked on its own.

GSTIN 27ABCPK1234F1Z5 → one GSTIN, not GSTIN + PAN

2 · Partial overlaps grow

If two finds only partly overlap, the span grows to cover both, instead of dropping one and leaving part of a number exposed.

3 · ID numbers beat names and addresses

If the AI marks an address that contains a phone number, the phone is cut out and labeled as a phone. The rest stays an address.

12 MG Road Pune 411001 ph 9876543210

4 · Repeats are caught everywhere

Once a value is found, every other exact repeat of it in the document is marked too. Whole words only, so "Ram" doesn't match inside "Ramesh".

Engineering log

What we found and changed

Found

One of Presidio's PAN patterns matched almost any 10-character word that has 4 digits in it, such as an order code.

Changed

Removed it and kept only the two real PAN shapes. Plain invoice numbers and codes are no longer flagged, and a test checks this.

Found

Presidio ignores any Aadhaar number that fails the checksum, so a typo or a made-up number next to the word "Aadhaar" would leak.

Changed

Added a backup rule. It only fires when an Aadhaar keyword is nearby, so random 12-digit numbers are still left alone.

Found

The plan assumed GSTIN needed a hand-written pattern.

Changed

Used Presidio's built-in GSTIN recognizer, which already checks the state code and structure. That meant less code and better accuracy.

Found

When the AI and the rules overlap, dropping either span could leave part of a value visible.

Changed

The merge rules grow spans instead of dropping them, and cut ID numbers out of addresses. Nothing found is ever left visible.
